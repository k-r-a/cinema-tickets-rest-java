# Cinema Tickets Code Test

## Objective

To assess your ability to build a simple API.

The scenario and requirements will be provided separately.

## Approach

`CinemaTicketsServiceImpl` calls the third-party services (PaymentService and SeatReservationService) only after 
successful validation of the whole request. 

- Payment is taken before seats are reserved. 
- No rollback logic is included as the brief mentioned that the third-party services would never fail.
- Prices for each ticket type, seat required and max number of tickets allowed per booking are configurable values 
specified in application.properties. Example configuration:
    - cinema.tickets.categories.infant.price=0.00
    - cinema.tickets.categories.infant.occupies-seat=false
    - cinema.tickets.categories.child.price=17.50
    - cinema.tickets.categories.adult.price=25.99 
    - cinema.booking.max-tickets-per-booking=25 
- A seat is allocated by default unless specified as occupies-seat=false. These values are bound to CinemaProperties 
and validated with Bean Validation, so startup fails if a ticket type has no price or a negative price, or if the 
maximum is missing or not positive.
- The total cost is summed per ticket type and rounded half up to 2 decimal places.
- Rejected Bookings (HTTP 400, ProblemDetail) if
    - Account id is missing, zero or negative
    - Ticket requests are missing, empty or contain a null entry
    - A ticket request has no type or a negative count
    - Total tickets (all types) is 0
    - Total tickets(all types) is more than max tickets allowed (25)
    - No adult ticket when child / infant tickets are requested
    - More infants than adults
- Malformed JSON, unknown ticket types and non-numeric counts are also returned as 400 by Spring's standard 
exception handling. Spring returns 405/415 for the wrong HTTP method/content type.

## Additional assumptions and interpretation of ambiguous rules
Following are in addition to already provided assumptions:
1. Infants count towards the 25 maximum tickets limit
2. Each infant sits on an adults lap, so infants cannot outnumber adults.
3. Multiple TicketRequest of the same type are summed. For e.g. `[ADULT x1, ADULT x1]` is summed as 2 adults.
4. TicketRequest with a zero count is allowed, but a negative count is rejected. A booking with no tickets is rejected.
5. Validation messages are returned to the client in the `detail` field of the problem response 
without any sensitive data.

## Changes to existing code
- `BookingConfirmation` was extended to include total cost and reserved seat count. The original 1 arg constructor 
remains for backward compatibility.
- `RestExceptionHandler` now maps `InvalidBookingException` to `400 Bad Request`.
- `cinema-tickets.yaml` request field names were corrected to the ones the existing domain records actually 
serialise (`ticketRequests`, `ticketCount`).

## API documentation
With the app running(`mvn spring-boot:run`), Swagger UI is at
<http://localhost:8080/swagger-ui.html> and the OpenAPI JSON at
<http://localhost:8080/v3/api-docs> (generated by springdoc-openapi).

## Example
```shell
curl -X POST http://localhost:8080/cinema/bookings \
  -H 'Content-Type: application/json' \
  -d '{ "accountId": 1234, "ticketRequests": [
          {"type": "ADULT", "ticketCount": 2},
          {"type": "CHILD", "ticketCount": 1},
          {"type": "INFANT", "ticketCount": 1}]}'
```
Response `201 Created`:

```json
{"accountId": 1234, "seatCount": 3, "totalCost":  69.48}
```

mvn test # unit tests
